What the gates caught

Each phase's verifier returned FAIL:fixable at least once, and each failure was a real defect rather than a formality. P1: cadre still held the kernel. P2: a criterion read generously in its own author's favour — an archived file cannot drift, but a file at HEAD reads as current. P3: an unmarked route-matching path, and a changelog asserting the opposite of the code it described.

Two failures were prose, not code, and no test covers prose. A commit message described a file the commit did not contain; a changelog said a function would be removed after the source had un-deprecated it. Both were found by a verifier reading artifacts, which is the only check that looks at what a document claims rather than what a program does.

P3's integration pass found a guard that had been passing while checking the wrong artifact: it resolved a legacy CLI on PATH reporting 0.13.2 rather than the kernel the repository pins at 0.14.2, and passed only because 0.13.2 sits exactly on the compatibility window's inclusive minimum.
