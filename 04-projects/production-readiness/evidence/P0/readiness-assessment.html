What blocks production

01

cadre-kernel is public with no licence — and cadre’s installer downloads it

legalgates distribution

A public repository with no licence is all-rights-reserved by default. Nobody has been granted the right to use, copy, or redistribute it.

That would be a footnote if the kernel stood alone. It does not: the plugin shim cadre generates fetches the kernel by version at install time — AGENTIC_SDLC_VERSION, in internal/generators/plugin_generation.go:235. So an Apache-2.0, publicly installable CLI ships an installer that reaches for a dependency nobody may lawfully use.

One file fixes it. Until it exists, every other item on this page is downstream of a distribution that cannot legally ship.

02

gloop presents itself as a public MIT SDK and is a private repo with no licence

legaldecision needed

Its README opens as “Gloop SDK — a powerful Go SDK for building AI agent orchestration systems” and carries three badges: Go Report Card, Go Reference, and License: MIT. The repository is private, has no LICENSE file tracked or untracked, and pkg.go.dev/github.com/deagy/gloop returns 404.

Two badges point at services that can only index public modules. The third asserts a grant of rights that does not exist, which is the one that matters.

This also settles a criterion that has been waiting on the wrong thing. AC-07b defers removing the deprecated selector.Select and roster.Select until gloop’s next major — to protect consumers. There are none: nothing imports gloop, not cadre, not recall, not cadre-kernel. The only caller of the deprecated selectors is gloop’s own CLI, at cmd/gloop/cmd/select.go:91. And the deprecation notice exists only in [Unreleased], so the promise has never shipped to anyone.

03

The knowledge store has no caller identity, and its own security document says so

stated bar unmetreal engineering

Every actor field — --decided-by, --deleted-by, --authorized-by — is a free-text string. roster/knowledge-store/SECURITY.md is unusually direct about what that costs:

“…caller-asserted strings, authenticated by nobody… an actor that stages as one name and decides as another satisfies both. So these enforce separation as declared, not separation in fact.”

Two of the four separation-of-duties checks compare two such strings. The document’s own conclusion is that production integration must derive staged_by and decided_by from authenticated claims rather than trusting the record. The retrieval audit log reaches the same verdict independently: no authenticated identity, no tenant or environment scope, no authorization decision, no returned citation ids — “production requirements this does not meet.”

This is the item that separates works from production, and the only one on this page that is a project rather than a task.

04

Retention and erasure of ingested content have no implementation

declared absent

No retention window is recorded for any content, nothing ages out, nothing reports what has expired, and no command deletes ingested content. The capability-parity goal closed these by declaring them absent across every document that touches them — the honest branch, and it does not make them present.

A steward asked to honour an erasure obligation has no tool here and leaves no evidence trail if they act by other means.

05

46 and 39 commits unreleased

reachability

cadre’s last release is cli-v0.6.5, 2026-08-19 — before two ultragoals’ worth of work. gloop’s is v0.2.0, 2026-08-20. Everything shipped since, including the CLI wires and the guards added today, exists only on main.

Work nobody can install is work nobody has.

06

Two residues: a live config bug, and a kernel with two release homes

issue #249split residue

Issue #249 reproduces against the current binary: from a directory under $HOME with no .git between, the config tier resolves as project-local when it should be global-fallback, and KNOWLEDGE_STORE_HOME is silently ignored. The cause is at internal/platform/paths.go:113 — the walk stats the candidate before testing the .git boundary, so with no project root it climbs to $HOME, where the global store’s own config is a valid project-local match.

The issue’s security claim no longer applies: it was written against Python, where the scope gates keyed on tier. The Go gate is unconditional and says why at internal/cli/knowledge.go:389. What survives is a correctness bug — and an issue that has cited deleted Python for three weeks.

Separately, cadre still tags kernel-v* and carries kernel release workflow while cadre-kernel publishes independently. One concern, two release homes — residue from the split that repo-consolidation existed to end.

What is genuinely strong

579 test files, and every guard added recently was falsified in both directions rather than assumed — the defect reintroduced and the check watched failing, then removed and watched passing.

All four green on their own runners. That was not true this morning: cadre had been red for ten consecutive pushes and gloop for four, each because a cross-repository guard built to refuse to skip under CI had been given no way to run.

The honesty layer is the real asset. SECURITY.md states its own limits precisely instead of hiding them — which is rarer than working code, and is the only reason this assessment took an hour. The gaps were already written down truthfully; the work was reading them.

Suggested order

  1. Licence cadre-kernel An afternoon. Unblocks the entire distribution, and nothing else can ship past it.
  2. Decide gloop: public or internal Public means the licence and badges become true first. Internal means the badges come out, the deprecated selectors can be deleted now, and AC-07b closes today instead of waiting for a v1.0 with no external reason to exist.
  3. Cut releases 85 commits across two repositories are currently unreachable by anyone who installs rather than clones.
  4. Fix #249, and correct the issue itself Test the .git boundary before the candidate in platform.FindFileAtProjectRoot, which both stores share; add the test the issue notes is missing; and strike the bypass claim that the Go rewrite already closed.
  5. Caller identity The one project rather than task. Until staged_by and decided_by come from authenticated claims, the separation-of-duties guarantees are declarations, and the documents already say so.
